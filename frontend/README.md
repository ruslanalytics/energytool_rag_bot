# Фронтенд ИИ-консультанта Energytool

Веб-чат для ИИ-консультанта сайта МТС Energytool. React + Vite + TypeScript + Zustand + TanStack Query. Бэкенд (FastAPI) запускается отдельно и не входит в этот каталог.

## Запуск в режиме разработки

1. Запустите бэкенд отдельно на `http://localhost:8000` (см. `API.md` в корне проекта).
2. В каталоге `frontend`:

   ```bash
   npm install
   npm run dev
   ```

3. Откройте адрес, который выведет Vite (обычно `http://localhost:5173`). Запросы к `/api` и `/health` автоматически проксируются на `http://localhost:8000` (настроено в `vite.config.ts`).

## Сборка

```bash
npm run build
```

Результат попадает в `frontend/dist`. По договорённости с бэкендом, `dist/index.html` отдаётся на `/`, а `dist/assets` — на `/assets` (бэкенд настраивается отдельно, в этом каталоге не меняется).

## Тесты

```bash
npm test
```

Тесты (`vitest`) запускаются без сети и без бэкенда — все обращения к `fetch` подменяются.

## Структура

```
frontend/
  src/
    main.tsx          — точка входа, подключение QueryClientProvider
    App.tsx            — старт сессии, разметка (сайдбар + чат), мутация отправки сообщения
    api.ts              — все обращения к бэкенду (fetch) и разбор ошибок
    types.ts            — типы ответов API
    store.ts            — состояние интерфейса (Zustand) + чтение/запись localStorage
    components/         — по одному файлу на компонент интерфейса
    utils/               — чистые функции (относительное время, определение предложения заявки)
    styles/
      tokens.css         — все цвета, шрифты, радиусы и отступы
      global.css         — базовые сбросы
```

## Как устроено состояние

- **TanStack Query** — все данные с сервера: список сессий (`['sessions']`), сообщения текущей сессии (`['messages', sessionId]`), отправка сообщения (мутация). Отправка сообщения сразу добавляет сообщение клиента в кэш (оптимistично), а после ответа бэкенда дописывает ответ бота вместе с `debug` и обновляет список сессий. Автоповторы для отправки сообщения отключены, чтобы не дублировать сообщения в диалоге при ошибке.
- **Zustand** (`store.ts`) — только состояние интерфейса: текущий `session_id` (сохраняется в `localStorage`), режим отладки (сохраняется в `localStorage`), какой экран открыт (чат или история — используется на узких экранах), черновик сообщения. Данные сервера в Zustand не дублируются.
- В `localStorage` хранятся только `energytool_session_id` и `energytool_debug_mode`. Тексты диалогов, ФИО и телефоны там не сохраняются — они живут только в кэше TanStack Query в памяти вкладки.

## Режим отладки

Переключатель «Отладка» находится в шапке чата. Состояние сохраняется в `localStorage` и переживает перезагрузку страницы. Во включённом режиме под каждым ответом консультанта появляется строка со временем ответа; при наличии источников её можно раскрыть — появится разбивка по времени (поиск / реранжирование / генерация) и список документов базы знаний с превью. Если бэкенд вернул `debug.error`, текст ошибки виден только в этом раскрытом блоке.

## Проверка основного сценария

1. Открыть чат — создаётся новая сессия (`POST /api/sessions`), `session_id` сохраняется в `localStorage`.
2. Задать первый вопрос — бот отвечает по базе знаний.
3. Задать второй вопрос — в конце ответа бота появляется абзац с предложением оформить заявку.
4. Написать «да» — бот просит ФИО (`state = lead_name`).
5. Ввести ФИО → бот просит телефон (`state = lead_phone`).
6. Ввести телефон (10–15 цифр) → бот просит компанию (`state = lead_company`).
7. Ввести компанию → бот подтверждает и присылает резюме диалога, `state` возвращается в `chat`.
8. Нажать «Новый чат» — создаётся новая сессия, экран очищается, прежняя сессия остаётся доступна в истории слева.
9. Открыть историю — предыдущий диалог виден в списке, с отметкой «Заявка оформлена».

## Встраивание в сайт Energytool

Чат — самостоятельное SPA, подходит для встраивания через `iframe`:

```html
<iframe
  src="https://<адрес-бэкенда>/"
  style="width: 100%; height: 480px; border: none; border-radius: 16px;"
  title="ИИ-консультант Energytool"
></iframe>
```

Поскольку бэкенд в проде отдаёт и статику, и API с одного origin, дополнительная настройка CORS на фронтенде не нужна. Минимальный размер, на который рассчитан интерфейс, — 320×480 px.
