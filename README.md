# energytool_rag_bot

ИИ-консультант для сайта МТС Energytool (кейс Hack&Change 2026). Ведёт клиента от описания проблемы до заявки менеджеру: ищет ответ по базе знаний Energytool (RAG), а когда клиент готов, собирает ФИО, телефон, компанию и формирует резюме диалога для менеджера.

## Структура

```
.
├── backend/
│   ├── app.py              FastAPI-приложение, роуты /api, /health, раздача фронтенда
│   ├── rag.py               поиск по базе знаний: чанкинг, эмбеддинги, ChromaDB, BM25
│   ├── lead_flow.py         логика диалога и сбора заявки (ФИО → телефон → компания)
│   ├── storage.py           хранение сессий, сообщений, заявок
│   ├── test_backend.py
│   └── env.example
├── frontend/                веб-чат (React + Vite + TypeScript), подробности — frontend/README.md
├── data/
│   └── knowledge-base.zip   база знаний Energytool — распаковывается и индексируется при старте
├── Dockerfile               сборка фронта (Node) и бэкенда (Python) в один образ
├── compose.yaml             запуск через docker compose
└── requirements.txt         зависимости Python-бэкенда
```

## Запуск через Docker

```bash
cp backend/env.example backend/.env   # заполнить, если нужны внешние ключи
docker compose up --build
```

- `http://localhost:8000/` — чат (бэкенд собирает фронтенд на этапе сборки образа и раздаёт его как статику)
- `http://localhost:8000/health` — статус индекса базы знаний
- `http://localhost:8000/docs` — Swagger

## Локальная разработка без Docker

Бэкенд:

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r ../requirements.txt
uvicorn app:app --reload --port 8000
```

Фронтенд, отдельным терминалом:

```bash
cd frontend
npm install
npm run dev
```

`vite.config.ts` проксирует `/api` и `/health` на `localhost:8000`, поэтому оба процесса работают вместе без дополнительной настройки CORS.

## API

REST-контракт бэкенда: `POST /api/sessions`, `GET /api/sessions`, `GET /api/sessions/{id}`, `POST /api/chat`, `GET /api/leads`, `GET /health`. Формат запросов/ответов и коды ошибок — в докстрингах `backend/app.py` и в Swagger (`/docs`).

## Переменные окружения

Задаются в `backend/.env` (создать из `backend/env.example`, в репозитории — только пустые плейсхолдеры, реальные ключи никогда не коммитятся).

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL` | адрес OpenAI-совместимого API для генерации ответов |
| `LLM_API_KEY` | ключ к этому API |
| `LLM_MODEL` | название модели для генерации (например, `gpt-4o-mini`, `qwen2.5-72b-instruct` — зависит от провайдера) |
| `EMBEDDER_API_KEY` | ключ API для получения эмбеддингов |
| `EMB_MODEL` | название модели эмбеддингов |
| `RERANKER_API_KEY` | ключ API для реранжирования |
| `RERANKER_MODEL` | название модели реранкера |
| `TOP_K` | сколько фрагментов базы знаний брать в контекст ответа |
| `MAX_TOKENS` | лимит длины ответа LLM |
| `TEMPERATURE` | температура генерации |

Модель **Qwen3.8-27B** (и эмбеддер BAAI/bge-m3, реранкер Qwen3 Reranker 8B), которую организаторы хакатона дают через свой API, доступна **только** внутри их собственной песочницы — при автоматической проверке `solution.py` на платформе. Снаружи (в том числе в этом Docker-контейнере, который запускается локально) этот ключ недоступен, его организаторы не публикуют. Поэтому для самостоятельного запуска нужен свой ключ от любого OpenAI-совместимого провайдера (OpenAI, OpenRouter, Groq, DeepSeek и т.п.) — вписывается в `backend/.env`, в репозиторий не попадает.

Без заполненных ключей бот запускается и отвечает, но без реальной LLM-генерации — см. «Ограничения» ниже.

## Проверка основного сценария

1. `cp backend/env.example backend/.env`, при необходимости заполнить ключи.
2. `docker compose up --build`.
3. Открыть `http://localhost:8000` — должен открыться чат (не пустая страница, не 404).
4. Задать вопрос по тарифам/оборудованию Energytool — бот должен ответить.
5. Задать второй вопрос — в конце ответа должно появиться предложение оформить заявку.
6. Написать «да» → ФИО → телефон (10–15 цифр) → название компании — в конце должно прийти подтверждение и резюме диалога.
7. `GET http://localhost:8000/health` — должен вернуть `{"status": "ok", "chunks": ...}`.

## Поиск по базе знаний

Эмбеддинги хранятся в ChromaDB, чанкинг — через `langchain-text-splitters`, поиск гибридный: векторный (ChromaDB) + BM25 (`bm25s`). Детали реализации — в `backend/rag.py`.

## Ограничения

- Без собственного ключа LLM (переменные `LLM_*` в `backend/.env` пустые) бот не генерирует полноценный консультационный ответ — ключ организаторов хакатона для этого недоступен за пределами их платформы автооценки.
- Реальных интеграций с CRM или почтой нет, заявка хранится внутри сервиса.
- После «Нового диалога» или закрытия чата контекст предыдущей сессии не используется, но сама история всех сессий (включая без заявки) сохраняется и доступна для просмотра.

## Стек

Backend: Python, FastAPI, ChromaDB, BM25 (bm25s). Frontend: React, Vite, TypeScript, Zustand, TanStack Query. Docker: двухстадийная сборка — Node собирает фронтенд, Python его раздаёт.
